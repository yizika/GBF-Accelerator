Windows 本地定制版（基于 2.5.1，维护分支 codex/local-cache-safety）

修改内容
1. 指定 --upstream-proxy 不再隐式关闭上游 TLS 校验。
2. Windows 启动及生成证书前收紧证书目录与已有私钥访问权限；保留原有证书。
   允许当前用户、SYSTEM 和管理员访问。权限操作失败时停止初始化。
   Windows PowerShell 调用有 15 秒超时。其他平台保持原有行为。
3. Import-ACGPCache.ps1 将旧缓存中的图片、音视频、字体等复制到新目录。
   不复制 JS、CSS、WASM、SVG、HTML 和未知类型，也不修改旧缓存。
   原有 JSON 元数据中的验证标记会清除，供程序重新校验。
4. 合入 v2.5.1 的中英日界面，以及上游 3171d36 的 OPTIONS 请求透传修复。

从之前的定制版升级
先通过托盘菜单退出旧程序，备份旧 GBF_Accelerator.exe，再仅替换这个 exe。
保留原目录的 config.json、certs/ 和 cache/，不要覆盖成包内的新用户默认配置。
ZeroOmega PAC 地址和 Clash 上游配置不需要改。无需迁移旧 ACGP 缓存。
如需回退，退出后恢复备份的 exe。不要通过官方二进制更新覆盖本地安全补丁。

试用
1. 解压到独立目录，运行 Start-Trial.cmd。
2. 上游预设为 http://127.0.0.1:7897，请核对 Clash 的 HTTP/混合端口。
3. TLS 校验开启，岛风模式和 LAN 关闭；保留预取功能。
4. 初次不会自动接管系统代理，也不会自动更新覆盖试用程序。
   新用户按界面流程安装本机证书，再在 ZeroOmega 使用 PAC：
   http://127.0.0.1:8124/proxy.pac
   已使用 ZeroOmega 时无需再开启加速器的系统 PAC。
5. 首次建议使用空缓存。复用 ACGP 缓存时，关闭加速器，在 PowerShell 执行：
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Import-ACGPCache.ps1 -Source "D:\ACGPower\cache\gbf\https" -Destination "D:\GBF-imported-cache"
   替换为实际路径；Source 应包含 assets 或 assets_en，Destination 必须不存在。
   在程序中选择新目录，执行缓存体检后再使用。不要重新选择旧缓存目录。
   迁移不证明素材与 CDN 原件完全一致；脚本等资源在实际请求时重新下载。
6. 停用时先关闭系统 PAC；不再使用本工具时，通过界面卸载它的根证书。
   不要分享 certs/ca.key。包内不包含任何用户证书、私钥或旧缓存。
